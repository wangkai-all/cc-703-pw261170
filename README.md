# 带业务约束的并发批次发布（本地分析仓演示）

一张按 **区域 + 方案编号** 保存的资源分配事实表，区域有可分配总量上限。
网页准备两批更正，让两个独立工作进程从**同一快照**分别计算、分别提交，
观察哪些批次被接受、拒绝重算或要求人工调整。

纯 Python 标准库实现（无第三方依赖），前端为原生 HTML/JS/SVG。

## 启动

```bash
./run.sh 8000          # 或 python3 -m src.pointwise.web --port 8000
# 打开 http://127.0.0.1:8000
```

## 测试（串行执行作为正确性对照）

```bash
python3 -m unittest discover -s tests -v
```

## 业务模型与三类约束（不承诺分析任意 SQL）

种子数据：R1（P101/P102/P103，上限 100，初始合计 80）、R2（P201/P202/P203，上限 60，初始合计 50）。
金额一律为整数，写入是对方案行的**绝对改写**。

| 约束 | 代码 | 性质 |
|---|---|---|
| 按区域求和 `SUM(amount) WHERE region=? <= cap(?)` | `region_sum_exceeded` | 额度类，依赖区域谓词读集合 |
| 更正金额非负 | `negative_amount` | 硬性，输入本身非法 |
| 方案/区域存在 | `plan_not_found` / `region_not_found` | 硬性，输入本身非法 |

## 核心机制

### 1. 谓词读集合，而不只是写集合行版本

两批可以改不同方案行、行版本毫无冲突，却依据同一区域剩余额度，合起来越限
（预置场景 **phantom_sum**：A 改 P101→60、B 改 P102→45，单独都合法，合计 115 > 100）。
校验器在评估约束时显式记录**实际读取**的内容（`models.RegionRead`）：

- 区域谓词文本与成员方案集合（成员关系变化 = 幻影问题）；
- 每个成员行的版本与快照金额；
- 区域上限版本；
- 写集合基于的行版本、方案维度版本。

提交端比对读集合与当前已提交状态，任何会改变这些判断的修改都构成冲突并触发
**锁内基于当前状态的完整重校验**。

### 2. 检查与发布是同一个不可插队动作

`CommitCoordinator.commit` 在一把提交锁内连续完成「冲突检测 → 全约束重校验 → apply」，
不存在"先检查、再发布"之间被插队的窗口。任何拒绝路径都在 `apply` 之前返回，
**拒绝时原事实版不变**（整库版本不增、行金额不动）。

### 3. 两类拒绝的区分

| 结果 | 含义 | 处理 |
|---|---|---|
| `accepted` | 锁内重校验通过，原子发布 | — |
| `rejected_recompute` | 读集合前提被并发提交改变（有冲突）且当前超限 | 可基于**新快照**重新计算 |
| `rejected_manual` | 输入本身违约（负值/方案缺失），或无冲突下自身超限 | 必须人工调整输入 |

系统**不会自动改小金额凑过上限**；重算只重建读集合，写入金额保持不变。

### 4. 幂等：接受已落地但响应丢失

提交结果按 `batch_id` 缓存。同一 ID 重试命中缓存，返回同一发布结果与同一发布版本，
`attempt` 递增，绝不重复发布（预置场景 **lost_response**）。

### 5. 两种校验粒度（可在网页切换）

- **region（默认，正确）**：区域谓词读集合 + 行版本，等价可串行化提交；
- **row（缺陷对照）**：只核对写集合行版本，无行冲突就直接发布。
  在 phantom_sum 下会错误地双接受并使区域合计越限（页面有越限警告），
  用来直观说明"只看行版本为什么不够"。

### 6. 串行基线与吞吐对照

`serial.SerialExecutor` 以同一协调器严格顺序执行；测试断言并发（region 模式）的
最终事实表必定等于某个串行顺序的结果，且多线程压力下区域合计永不越限。
压测在同一工作负载下对照串行/并发墙钟时间：计算延迟发生在提交锁之外可重叠，
而提交临界区仍串行化——两模式接受集合与最终版本一致，差别只在吞吐。

## 代码结构

```
src/pointwise/
  models.py       行/上限/快照/写项/谓词读集合/冲突证据/提交结果
  store.py        行版本与整库版本、copy-on-read 快照、提交 apply、事件历史
  constraints.py  暂存器 + 三类约束校验，构建谓词读集合（SnapshotView/LiveView）
  coordinator.py  提交锁、读集合冲突检测、锁内原子重校验即发布、幂等缓存
  serial.py       串行执行基线
  scenarios.py    确定性场景重放（共享快照、提交顺序、重算重试、时间线）
  benchmark.py    真实线程并发 vs 串行吞吐压测
  engine.py       服务门面、种子数据、七个预置教学场景
  web.py          ThreadingHTTPServer + JSON API
web/              index.html / app.js（时间线、冲突依据、读集合、吞吐柱状图）
tests/            18 项 unittest
```

## HTTP API 摘要

| 方法/路径 | 作用 |
|---|---|
| `GET /api/state` | 事实表、上限、事件历史、协调器统计、幂等缓存键 |
| `POST /api/reset` | 重置种子数据并清空结果缓存 |
| `POST /api/granularity` | `region` / `row` 校验粒度切换 |
| `POST /api/scenario/run` | 重放预置场景，返回时间线、裁决依据与最终状态 |
| `GET /api/scenarios` | 预置场景清单 |
| `POST /api/stage` / `POST /api/commit` | 单批暂存 / 提交（含同 ID 幂等重试） |
| `POST /api/commit-parallel` | 两批共享快照、屏障同步后真实线程并发提交 |
| `POST /api/benchmark` | 串行 vs 并发吞吐对照 |
